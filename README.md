# SlimTucci Workout Diary

A personal workout diary PWA for Alexander Tucci (SlimTucci). Plain HTML/CSS/JS with no build step, backend, or accounts. All data stays on the phone in localStorage.

## Files
- `index.html`, `styles.css`, `app.js`: the app
- `manifest.webmanifest`, `icons/`: home-screen install
- `sw.js`: offline cache. **Bump `VERSION` in sw.js on every deploy** so phones pick up the update.
- `tests/e2e_test.py`: Playwright test at 390x844
- `screenshots/`: phone screenshots

## Weeks
Weeks run **Sunday → Saturday**. Week 1 is the Sun–Sat week that contains the program start date (set under More). Labels look like `Week 3 · Oct 4–10`.

## Run locally
    python3 -m http.server 8765        # in this folder, then open http://localhost:8765
    python3 tests/e2e_test.py          # in another shell (needs: pip install playwright && python3 -m playwright install chromium)

## Deploy (any static HTTPS host)
Upload this folder as-is. `tests/`, `screenshots/` and `README.md` are optional.
- GitHub Pages: push to a repo, then Settings → Pages → deploy from the branch root (`.nojekyll` is included).
- Netlify: `npx netlify-cli deploy --prod --dir .`
- Cloudflare Pages: `npx wrangler pages deploy . --project-name slimtucci-diary`

## Backups
Go to More → Export JSON to download `slimtucci-diary-YYYY-MM-DD.json`. Use Import JSON to replace this phone's data with a backup.

## v3 (Oct 7, 2026)
- New look: light theme by default (deep teal accent, green for completed sets), automatic dark mode via `prefers-color-scheme`. Palette passes WCAG AA.
- Tappable Sun–Sat days: tap a day to see its logged and planned workouts. From the selected day you can log a blank workout, start a template, or plan a template for that day.
- Built-in exercise library in `exercises-library.js` (generated by `tools/build_library.py`), 627 movements in 10 categories. Searchable, typo-tolerant picker with category chips, "My exercises" listed first, and "Add custom".
- The log has a sticky **+ Add exercise / Finish** bar.

## v4 (Oct 7, 2026)
- **Macros** tab: macro calculator (Mifflin-St Jeor, or Katch-McArdle with body-fat %), goal and intensity, protein/fat/carb targets, and a "Today's targets" strip on Today. Logic is in `macros-calc.js`.

## v5 (Oct 7, 2026): Burn today + WHOOP
- **Burn today** card on Today, below the targets strip (the strip itself is unchanged). Tap it to enter today's total calories burned (source **Manual**). It fills automatically from **WHOOP** once connected; a manual number for today wins over WHOOP.
- **Adjustment rule** (`computeBurnExtra` in `macros-calc.js`): baseline = TDEE. Extra = (burn − TDEE) × 50% on a cut or 75% on maintain/bulk, rounded to 5 kcal and clamped to 0…+800 kcal. All of it goes to carbs (÷4, rounded to 5 g); protein and fat don't change. Base targets stay as they are. Macros shows an extra "Adjusted today" line.
- **WHOOP**: a card on Macros (below the targets) and **More → Connections**. `config.js` holds `WHOOP_WORKER_URL`. While it's `''` the card shows **Setup needed** with the 3 setup steps. Set it to the deployed Worker URL to go live.
- The phone stores only a random per-device session id (`localStorage['slimtucci-whoop-v1']`), never WHOOP tokens and never the client secret. That key is not part of Export.
- The Cloudflare Worker bridge is intentionally **not in this repo** (WHOOP credentials must never be in an open-source repo). It lives in the private ops folder `business-ops/whoop-worker/` with its own `SETUP.md`.
